# bids-spider 项目功能说明

> 整理日期：2026-09-21（同步最新能力：today 两段式 / today_db / 补爬顺带收录 / 自动归档 / 个人机会自动分析）

## 一、项目定位：解决什么问题

**核心问题**：全国 29 个省市自治区（北京、天津、河北、辽宁…）的招标/采购公告分散在各自独立的政府采购网和公共资源交易平台，人工逐站查询极其低效——站点格式不一、结构各异、部分有验证码反爬。

**项目价值**：一套**自动化的招标商机采集系统**——每天自动把 29 个地区的招标公告抓下来、清洗入库、导出 Excel、生成需求洞察报告，让用户"一次打开一个 Excel / 一份报告"即可掌握全国商机，不再逐站翻网页。

## 二、解决的 7 个具体问题及实现方式

### 1. 29 个异构网站的采集

**问题**：29 个站点没有统一格式——有 DOM 列表页（北京/河北）、JSON 接口（辽宁/湖南/贵州）、政采云平台（新疆/贵州）、带验证码的（黑龙江/甘肃/陕西/河南）等。

**解决**：每个地区一个爬虫文件（`crawler/` 下 29 个 `.py`），继承统一基类 `BaseCrawler`。每个爬虫针对该站点的真实结构定制"列表解析 + 详情获取"，互不干扰。

**技术底座**：Playwright 无头浏览器 + playwright-stealth（伪装真实浏览器，绕过 `navigator.webdriver` 检测），可处理 JS 动态渲染页面。

### 2. 反爬对抗与验证码

**问题**：多个站点有反爬措施，验证码是最大障碍。

**解决**（`utils/captcha.py`）：
- **ddddocr 本地 OCR**：黑龙江/甘肃/陕西/河南的 4 位字符验证码，加载页面 → 抓取验证码图 → ddddocr 识别 → 填入并提交，失败自动重试（最多 6-8 次）
- **随机延时**：`_random_sleep` 模拟人工浏览节奏
- **请求头复用**：贵州等站点捕获页面真实请求头（含 Cookie）再调用接口，降低触发风控概率
- **详情容错重试**：湖南/贵州/山东的详情接口异常时自动重试 3 次

### 3. 增量去重与数据入库

**问题**：重复抓取会产生大量冗余数据。

**解决**（`utils/es.py`）：三重去重机制
1. **ES 预检**：运行前查库，`href` 已在库中的直接跳过（跨批次去重）
2. **内存字典**：`self.tenders` 以 `href` 为 key（单批次内去重）
3. **ES 幂等写入**：以 `href` 作为文档 `_id`，即使写重也是覆盖而非新增

### 4. 按日期抓取（今日/指定日/历史查询）

**问题**：用户需要"今天发布了什么"或"某一天的历史商机"。

**解决**（`crawler/base_crawler.py` 的 `run_by_date` + `fast_run.py` 的命令体系）：
- **方案 A（原生日期参数）**：内蒙古等站点接口直接支持 `startTime/endTime` 参数，精准定位（内蒙古当前接口 500 故障，见能力边界）
- **扫描早停（默认）**：其他站点复用列表翻页，遇早于目标日期的公告立即停止（`_DateBoundaryReached` 异常）；**翻页深度由目标日期决定**——已移除固定 8 页 / 100 条硬截断，今日发布很多时仍会继续翻页直到覆盖昨日，页数仅作防死循环兜底（上限 200 页）
- **严格过滤兜底**：最终按日期范围二次过滤，确保零误收

命令速查：

| 命令 | 行为 | 适用场景 |
|---|---|---|
| `today` | 两段式：先查库整理今日已有，再增量爬补新增 | 获取今日完整商机（推荐） |
| `today_db` | 只查 ES 今日已入库数据，不爬网站 | 快速看今日已有数据（秒出） |
| `by_date <date>` | 重新爬网站该日公告 | 补抓缺失数据 |
| `db_date <date>` | 只查 ES 历史某天，不碰网站 | 快速看历史 |

### 5. 多地区并行提速

**问题**：29 个地区串行跑太慢。

**解决**：`xargs -P 4` 并行批跑（见 `.trae/rules/project_rules.md` 2.3 节），4 路并发，各地区打不同网站互不冲突；每地区独立日志，结果汇总到 JSONL。**必须带 `--no-summary`**——并行进程只抓取+写 jsonl、不覆盖汇总文件，由随后的 `summarize` 统一合并。

### 6. 数据导出与需求洞察报告

**问题**：抓到的数据要能直接看、能分析。

**解决**：
- **Excel 导出**：中文列名（地区/公告链接/**商机标题**/发布日期/抓取日期/**商机详情**/详情截断），正文用 html2text 转纯文本，超长标 `truncated=是`
- **需求洞察报告**（`analyze_today.py`）：抓取完**自动**生成——统计品类（10 类关键词投票）、公告类型、采购人主体（6 类）、金额（兼容元/万元）、区域分布，产出 5 张图表 + 咨询级 Markdown 报告

### 7. 完整性与自动化

**问题**：单次抓取会漏掉"触发时刻之后"发布的当天公告；output/logs 目录会无限增长。

**解决**：
- **补爬顺带收录**：`by_date` 补任意历史日时，列表页扫到的今天公告一并入库（不丢弃），供 `today_db`/`today` 直接复用
- **每日 10:00 补抓昨日**（定时任务）：补全昨天全天公告；顺带收录今天凌晨~10:00 已发布的
- **归档清理**（每日 09:00 定时任务）：output 与 logs 超 7 天的文件自动压缩归档；`runtime.log` 超 50MB 自动轮转
- **单地区 Excel 用完即删**：汇总后自动清理，数据全量在 ES 可随时重导出

### 8. 个人业务机会自动分析

**问题**：用户业务是**服务器销售/IT/AI**方向，每天上千条商机里只有少数几条真正相关，逐条翻 Excel 找机会效率低。

**解决**（`analyze_opportunities.py` + `config/opportunities.json`）：
- **规则引擎筛选**：按业务配置（核心/次要/排除关键词）对当日商机打分——标题命中**排除关键词**（复印纸/物业/食堂…）直接剔除；标题命中**核心关键词**（服务器/算力/AI/大模型/信创/数据中心…）→ **直接相关**；标题命中**次要关键词**（信息化/系统集成/运维…）→ **相关**；仅正文反复命中核心词 → **意向线索**（弱信号）
- **三档产出**：相关度分级，重点跟进直接相关档
- **LLM 精读（可选）**：配置 `LLM精读.启用=true` 并填入 api_key 后，对大金额+直接相关的 top 机会调用大模型识别隐性机会、输出深度洞察（调用失败自动降级为纯规则引擎）
- **全自动**：`today` / `by_date` / `summarize` / `db_date` 跑完**自动附带**生成，也可独立运行 `python analyze_opportunities.py <date>`
- **产物（按日期归档在 `output/<date>/`）**：`output/<date>/机会清单_<date>.xlsx`（地区/链接/标题/类型/相关度/匹配词/金额）+ `output/<date>/机会分析_<date>.md`（分档清单 + 大金额 TOP + 可选 LLM 洞察）
- **可配置**：业务方向、关键词、排除词、关注地区、金额区间、LLM 开关全在 `config/opportunities.json`，改配置即生效

## 三、系统架构

```
                     ┌─────────────────────────────────────┐
                     │  fast_run.py（命令入口）              │
                     │  today / today_db / by_date          │
                     │  db_date / summarize                 │
                     └──────────────┬──────────────────────┘
                                    │ 并行批跑 (xargs -P 4)
        ┌───────────────────────────▼───────────────────────────┐
        │  29 个地区爬虫 (crawler/*.py)  继承 BaseCrawler       │
        │  Playwright + stealth + ddddocr 验证码 + 随机延时      │
        └───────────────────────────┬───────────────────────────┘
                                    │
              ┌─────────────────────┼──────────────────────┐
              ▼                     ▼                      ▼
     Elasticsearch             Excel (output/)      分析报告
     (tenders 索引)            按日期子目录          output/<date>/
     href 幂等去重              output/<date>/        需求洞察报告_<date>.md
                              date_<date>.xlsx      + charts/ 图表 + 机会分析
```

**核心组件**：
- `crawler/base_crawler.py` — 基类：Tender 模型、ES 存取、Excel 导出、日期模式（含补爬顺带收录今日公告）
- `utils/es.py` — ES 客户端（保存/批量/查询/幂等）
- `utils/captcha.py` — ddddocr/百度 OCR/云码
- `fast_run.py` — 命令入口 + 并行调度 + 汇总 + 单地区 Excel 自动清理
- `analyze_today.py` — 洞察报告生成
- `analyze_opportunities.py` — 个人业务机会筛选（规则引擎 + 可选 LLM 精读）
- `config/opportunities.json` — 机会分析业务配置（关键词 / 排除词 / LLM 开关）
- `scripts/backfill_details.py` — 按缺失清单补爬详情回填
- `scripts/backfill_shandong.py` — 山东缺失详情回填
- `scripts/archive_output.py` — output/logs 目录自动归档（超 7 天压缩）

## 四、用户视角的典型使用流程

1. **获取今日商机**：`python fast_run.py today` → 先查库整理今日已有（秒出）→ 再增量爬补新增；或 `today_db` 只查库
2. **看成果**：`python fast_run.py summarize <date>` → 得到合并 Excel + 自动生成的洞察报告 + **个人机会清单**（机会清单_<date>.xlsx / 机会分析_<date>.md）
3. **看历史**：`python fast_run.py db_date 2026-09-10` → 直接从库查某天
4. **补数据**：详情缺失时 `python scripts/backfill_details.py` 补爬回填
5. **调机会配置**：编辑 `config/opportunities.json`（关键词/排除词/LLM 开关）→ 重跑 `analyze_opportunities.py <date>` 即生效
6. **自动化**：每天 10:00 自动补抓昨日（顺带收录今日公告）；每天 09:00 自动归档超 7 天旧文件

## 五、当前能力边界（已知限制）

| 限制 | 说明 |
|---|---|
| 上海不可用 | IP 被封（420 Blacklist），需换网络 |
| 内蒙古不可用 | 接口持续 500 系统错误（2026-09-18 起），待站点恢复 |
| 云南部分受限 | 翻页遇服务端 406 风控，仅首页 10 条 |
| 江苏/江西次日补抓无效 | 江苏列表只显示"访问当天"、江西分页器窗口约 60 条——次日补抓看不到昨日，昨日数据靠当天抓取顺带收录兜底（数据不丢） |
| 贵州意向公告 | 文字点选验证码（非字符型），需错峰（凌晨）或打码平台 |
| 金额提取率 ~13% | 受各平台披露完整度限制 |
| 天津数字 ID | 部分公告 href 为超大整数，Excel 精度丢失后无法还原 |

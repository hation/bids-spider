# bids-spider 项目功能说明

> 整理日期：2026-09-18

## 一、项目定位：解决什么问题

**核心问题**：全国 29 个省市自治区（北京、天津、河北、辽宁…）的招标/采购公告分散在各自独立的政府采购网和公共资源交易平台，人工逐站查询极其低效——站点格式不一、结构各异、部分有验证码反爬。

**项目价值**：一套**自动化的招标商机采集系统**——每天自动把 29 个地区的招标公告抓下来、清洗入库、导出 Excel、生成需求洞察报告，让用户"一次打开一个 Excel / 一份报告"即可掌握全国商机，不再逐站翻网页。

## 二、解决的 6 个具体问题及实现方式

### 1. 29 个异构网站的采集

**问题**：29 个站点没有统一格式——有 DOM 列表页（北京/河北）、JSON 接口（辽宁/湖南/贵州）、政采云平台（新疆/贵州）、带验证码的（黑龙江/甘肃/陕西/河南）等。

**解决**：每个地区一个爬虫文件（`crawler/` 下 29 个 `.py`），继承统一基类 `BaseCrawler`。每个爬虫针对该站点的真实结构定制"列表解析 + 详情获取"，互不干扰。

**技术底座**：Playwright 无头浏览器 + playwright-stealth（伪装真实浏览器，绕过 `navigator.webdriver` 检测），可处理 JS 动态渲染页面。

### 2. 反爬对抗与验证码

**问题**：多个站点有反爬措施，验证码是最大障碍。

**解决**（`utils/captcha.py`）：
- **ddddocr 本地 OCR**：黑龙江/甘肃/陕西/河南的 4 位字符验证码，加载页面 → 抓取验证码图 → ddddocr 识别 → 填入并提交，失败自动重试（最多 6-8 次）
- **随机延时**：`_random_sleep` 模拟人工浏览节奏
- **请求头复用**：贵州等站点捕获页面真实请求头（含 Cookie）再调用接口，降低触发风控概率
- **详情容错重试**：湖南/贵州/山东的详情接口异常时自动重试 3 次

### 3. 增量去重与数据入库

**问题**：重复抓取会产生大量冗余数据。

**解决**（`utils/es.py`）：三重去重机制
1. **ES 预检**：运行前查库，`href` 已在库中的直接跳过（跨批次去重）
2. **内存字典**：`self.tenders` 以 `href` 为 key（单批次内去重）
3. **ES 幂等写入**：以 `href` 作为文档 `_id`，即使写重也是覆盖而非新增

### 4. 按日期抓取（今日/指定日/历史查询）

**问题**：用户需要"今天发布了什么"或"某一天的历史商机"。

**解决**（`crawler/base_crawler.py` 的 `run_by_date` + `fast_run.py` 的命令体系）：
- **方案 A（原生日期参数）**：内蒙古等站点接口直接支持 `startTime/endTime` 参数，精准定位
- **扫描早停（回退）**：其他站点复用列表翻页，遇早于目标日期的公告立即停止（`_DateBoundaryReached` 异常）
- **严格过滤兜底**：最终按日期范围二次过滤，确保零误收

三条命令：

| 命令 | 行为 |
|---|---|
| `today` | 抓今天全部地区 |
| `by_date <date>` | 重新爬网站指定日 |
| `db_date <date>` | 只查 ES 历史某天，不碰网站 |

### 5. 多地区并行提速

**问题**：29 个地区串行跑太慢。

**解决**：`xargs -P 4` 并行批跑（见 `.trae/rules/project_rules.md` 2.3 节），4 路并发，各地区打不同网站互不冲突；每地区独立日志，结果汇总到 JSONL。

### 6. 数据导出与需求洞察报告

**问题**：抓到的数据要能直接看、能分析。

**解决**：
- **Excel 导出**：中文列名（地区/公告链接/**商机标题**/发布日期/抓取日期/**商机详情**/详情截断），正文用 html2text 转纯文本，超长标 `truncated=是`
- **需求洞察报告**（`analyze_today.py`）：抓取完**自动**生成——统计品类（10 类关键词投票）、公告类型、采购人主体（6 类）、金额（兼容元/万元）、区域分布，产出 5 张图表 + 咨询级 Markdown 报告

## 三、系统架构

```
                     ┌─────────────────────────────────────┐
                     │  fast_run.py（命令入口）              │
                     │  today / by_date / db_date / summarize│
                     └──────────────┬──────────────────────┘
                                    │ 并行批跑 (xargs -P 4)
        ┌───────────────────────────▼───────────────────────────┐
        │  29 个地区爬虫 (crawler/*.py)  继承 BaseCrawler       │
        │  Playwright + stealth + ddddocr 验证码 + 随机延时      │
        └───────────────────────────┬───────────────────────────┘
                                    │
              ┌─────────────────────┼──────────────────────┐
              ▼                     ▼                      ▼
     Elasticsearch             Excel (output/)      分析报告
     (tenders 索引)            中文列名              需求洞察报告_<date>.md
     href 幂等去重              date_<date>.xlsx     + charts/ 图表
```

**核心组件**：
- `crawler/base_crawler.py` — 基类：Tender 模型、ES 存取、Excel 导出、日期模式
- `utils/es.py` — ES 客户端（保存/批量/查询/幂等）
- `utils/captcha.py` — ddddocr/百度 OCR/云码
- `fast_run.py` — 命令入口 + 并行调度 + 汇总
- `analyze_today.py` — 洞察报告生成
- `scripts/` — 详情补爬工具（backfill_details / backfill_shandong）

## 四、用户视角的典型使用流程

1. **每日例行**：`python fast_run.py today`（或 29 地区并行批跑）→ 自动入库 ES
2. **看成果**：`python fast_run.py summarize <date>` → 得到合并 Excel + 自动生成的洞察报告
3. **看历史**：`python fast_run.py db_date 2026-09-10` → 直接从库查某天
4. **补数据**：详情缺失时 `python scripts/backfill_details.py` 补爬回填

## 五、当前能力边界（已知限制）

| 限制 | 说明 |
|---|---|
| 上海不可用 | IP 被封（420 Blacklist），需换网络 |
| 云南部分受限 | 翻页遇服务端 406 风控，仅首页 10 条 |
| 贵州意向公告 | 文字点选验证码（非字符型），需错峰（凌晨）或打码平台 |
| 金额提取率 ~13% | 受各平台披露完整度限制 |
| 天津数字 ID | 部分公告 href 为超大整数，Excel 精度丢失后无法还原 |

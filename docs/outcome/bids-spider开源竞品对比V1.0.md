## 1 对比范围与分层

bids-spider 是面向中国政府采购网的招标公告爬虫项目。按"与目标项目定位相似度"分层，可比对象分三类：

| 层级 | 代表对象 | 与本项目关系 |
| ---- | ---- | ---- |
| 直接竞品 | 开源招标/采购信息采集项目（如 bid-collection、各类 GitHub 招标爬虫） | 同品类，解决同一问题 |
| 应用平台 | 千里马招标网、剑鱼标讯、乙方宝、中国政府采购网（官方源） | 商业化/官方聚合平台，面向无开发能力用户 |
| 框架与工具 | Scrapy、DrissionPage、Playwright、requests+lxml | 实现爬虫的通用框架，非直接竞争，属可选实现路径 |

> 说明：招标爬虫领域公开的开源项目数量多但普遍碎片化（多为个人维护的脚本仓库，Star 量低），检索到的高质量公开参考以商业平台官网资料与通用爬虫框架为主，以下对比基于 2026-09-17 时点的公开信息。

## 2 直接竞品对比（开源采集项目）

| 维度 | bids-spider（本项目） | bid-collection（开源 Skill） |
| ---- | ---- | ---- |
| 定位 | 招标公告采集 + 结构化入库（ES/MongoDB） | 招标采购商机收集 Agent Skill（Claude Code） |
| 形态 | Python 脚本/爬虫类，手动运行 | npm 包 + Claude Code 斜杠命令（/bid-collection scan 等） |
| 数据源 | 各省政府采购网/公共资源交易平台 | 政府平台（ccgp 等）+ 央企采购 + 行业站点 + 第三方聚合器 |
| 处理深度 | 原始采集入库，含正文 HTML 抓取 | 商机筛选 + 10 条业务线匹配 + 优先级打分（Track Weight × Budget × Timeliness × Buyer） |
| 自动化 | 手动运行，增量去重 | 支持 monitor 定时后台监控 |
| 交付 | 自建 ES/Excel | 结构化商机报告 |
| 开源协议 | 仓库未标注协议（按源码推断） | MIT |
| 适用人群 | 有开发能力的个人/团队，自建标讯库 | 使用 Claude Code 的开发者，侧重业务商机 |

补充开源参照（碎片化案例）：

- **通用 Python 招标爬虫教程/脚本**：大量以 requests + BeautifulSoup/lxml 抓取中国政府采购网（如 ccgp.gov.cn 搜索接口）的案例，抓取品目/类别/页数循环，存 MySQL。特点是单站单脚本、无工程化封装，与本项目旧版 `ccgp.py` 思路类似。
- **工程化采集方案（学术）**：西安石油大学论文提出基于 Scrapy 的政府采购数据采集方案，内置定时增量爬取、异步加载、动态代理、异步存储，属于学术级工程化设计；本项目未采用 Scrapy，走 requests/Playwright 手写链路，工程化程度低于该方案，但代码更贴近实际站点适配。

## 6 相对优势与短板

### 6.1 相对优势

- **开源免费、数据自主**：不依赖商业平台订阅，自建数据仓库，数据归属可控。
- **两代架构并存提供适配参考**：配置驱动模式降低了"声明式接入新站点"的认知门槛；Playwright 真实浏览器 + Stealth 对反爬较强的政务站点有更贴近真实访问的抓取效果。
- **增量幂等去重**：以 href 作文档 ID 写入 ES，重复运行不产生重复数据，配合增量/历史双模式，适合长期持续采集。
- **结构清晰可扩展**：省份爬虫按 `crawler/<省>.py` 独立组织，接入新省只需实现 `_crawl` 钩子。

### 6.2 相对短板

- **无生产化能力**：无任务调度、代理池、分布式、告警，无法支撑大规模高频采集，需使用者自行补齐。
- **无面向业务用户的交付层**：无 UI、推送、订阅、关键词在线筛选，商业平台的核心增值（商机匹配、竞对分析）全部缺失。
- **站点适配脆弱**：各省定位器/接口参数硬编码在代码中，站点改版即失效，需持续人工维护；辽宁详情页正文抓取仍是 TODO。
- **维护与安全风险**：个人项目、无开源协议标注、无 CI；ES 口令、OCR Key 硬编码于源码，存在凭据泄露风险。
- **数据质量有限**：仅采集公告原始字段（标题/日期/正文），未抽取预算、采购人、联系方式等结构化字段，与商业平台的数据深度差距明显。
